## Background

TBR (Tree Bisection and Reconnection) is a more aggressive tree topology
operator than SPR. Where SPR prunes a subtree and reattaches it at a new
location, TBR additionally **reroots the pruned subtree** before
reattaching, giving it access to topologies that SPR cannot reach in a
single step. This makes TBR a superset of SPR: every SPR move is a TBR
move (with no rerooting), but not vice versa.

### When TBR is useful

TBR proposals are more expensive per iteration than SPR (larger proposal
kernel → more candidate topologies), but can escape local optima that
SPR gets stuck in. On large trees (50+ taxa), SPR acceptance rates can
drop below 1%, and the chain mixes poorly even with Gibbs-SPR. TBR's
ability to rearrange the pruned subtree before reattachment gives it a
qualitatively different exploration pattern.

The M-091 mixing validation showed that on small trees (23 taxa), baseline
SPR is already efficient (ESS/second). TBR is therefore positioned as an
opt-in move for larger analyses where mixing diagnostics indicate poor
topology exploration.

## Algorithm

### TBR on unrooted trees (parent/child vector representation)

The MkPrime tree is stored as parent/child integer vectors in canonical
preorder, with relative branch lengths (`relBrLengths`) and a scalar
`treeLength`. The tree is unrooted but stored with a formal root node
(nTip + 1). All operations are on this representation.

**Steps:**

1. **Select prune edge.** Uniformly pick an internal edge (u → v) where
   `parent[row] != root`. This is identical to the SPR prune selection.
   Let `u` be the parent node and `v` the child node of the pruned edge.

2. **Detach subtree.** Suppress node `u` from the backbone:
   - Find `u`'s parent edge (`grandparent → u`) and `v`'s sibling edge
     (`u → w`).
   - Contract: set `grandparent → w` with branch length =
     `len(grandparent→u) + len(u→w)`.
   - This leaves two components: the **backbone** (tree minus subtree at v)
     and the **pruned subtree** (rooted at v via the old `u→v` edge).

3. **Rerooting the pruned subtree** (the TBR-specific step).
   - If `v` is a tip, skip this step (nothing to reroot).
   - If `v` is internal, uniformly select an edge within the pruned subtree.
     Call the selected edge's child node `r`.
   - Reroot the pruned subtree at edge (parent(r) → r): insert a new
     internal root along this edge, splitting it by fraction `σ ~ Uniform(0,1)`.
     The old root of the pruned subtree (`v`) becomes an ordinary internal node.
   - After rerooting, the pruned subtree has a new "attachment node" at the
     top (the node that will be inserted into the backbone).

   **Simplified rerooting for parent/child vectors:** Rather than literally
   rerooting the subtree, we can achieve the same topological effect by:
   (a) selecting a random edge (p_r → r) within the pruned subtree,
   (b) this defines the new attachment point — the subtree will be attached
       to the backbone such that `r` and the rest of the pruned subtree
       are on opposite sides of the insertion point.

   Implementation approach: reverse the path from `v` to `r` within the
   pruned subtree, flipping parent–child relationships along the path and
   redistributing branch lengths. This is equivalent to `ape::root()` on
   the subtree but done in-place on the parent/child vectors.

4. **Select regraft edge.** Uniformly pick an edge in the backbone (same
   candidate set as SPR: not incident to `u`, not in the pruned subtree).

5. **Reattach.** Insert the (possibly rerooted) pruned subtree onto the
   regraft edge, splitting it at position `τ ~ Uniform(0,1)`.

6. **Canonical reorder.** Call `TreeTools::preorder_weighted_impl()` to
   renumber nodes and sort edges into canonical preorder, carrying branch
   lengths along.

### Hastings ratio

The Hastings ratio has three components:

1. **Regraft edge Jacobian** (same as SPR):
   `log(len_regraft) - log(len_merge)`, where `len_merge` is the combined
   length of the two edges merged during pruning.

2. **Rerooting Jacobian:** When the pruned subtree is rerooted at edge
   (p_r → r) with fraction σ, and the original root edge had length
   `len_orig`, we split one edge (of length `len_reroot_edge`) and merge
   two edges at the old root position (combined length `len_old_root_merge`):

   `log(len_reroot_edge) - log(len_old_root_merge)`

   If the subtree is a single tip or the identity reroot is chosen (edge
   incident to v), this component is 0.

3. **Proposal ratio for reroot edge count:** Let `n_sub_edges_fwd` be the
   number of edges in the pruned subtree (candidates for rerooting in the
   forward direction) and `n_sub_edges_rev` in the reverse direction.
   For the identity reroot (no actual rerooting), these are equal. In
   general:

   `log(n_sub_edges_fwd) - log(n_sub_edges_rev)`

   On an unrooted tree stored as a rooted structure, the number of internal
   edges in the pruned subtree is the same before and after rerooting
   (same number of nodes), so this ratio is **0**. The number of edges
   does not change because rerooting just redirects edges; it doesn't add
   or remove any.

**Combined Hastings ratio:**

```
logHR = log(len_regraft / len_merge) + log(len_reroot_edge / len_old_root_merge)
```

The second term is 0 when no rerooting occurs (v is a tip, or identity
reroot selected). When rerooting does occur, both terms contribute.

**Special case — v is a tip:** TBR reduces exactly to SPR. The reroot
step is skipped and the Hastings ratio is the standard SPR ratio.

### Step 1: `tbr_proposal_impl()` in `src/proposals.cpp`

The core C++ function, following the same pattern as `spr_proposal_impl()`:

```cpp
List tbr_proposal_impl(IntegerVector parent, IntegerVector child,
                       int nTip, double treeLength,
                       NumericVector relBrLengths);
```

**Internal helper:** `reroot_subtree()` — given the pruned subtree (identified
by which nodes are descendants of `v`), a target rerooting edge, and a
split fraction σ, modify the parent/child/branch-length vectors in place
to reverse the path from old root to new root.

**Return value:** Same as SPR — `List` with `parent`, `child`,
`rel_br_lengths`, `logHastings`.

Also add an Rcpp-exported wrapper `tbr_proposal()` for R-level testing.

### Step 2: MCMC engine integration

### Step 3: R-side registration

### Step 4: Tests

`tests/testthat/test-tbr.R`:

1. **Topology validity:** TBR proposal returns a valid tree (correct nTip,
   no cycles, all tips present, valid preorder).
2. **Reduces to SPR for tip pruning:** When the pruned subtree is a single
   tip, the result is topologically reachable by SPR.
3. **Rerooting correctness:** For a known tree, manually verify that
   rerooting a pruned subtree produces the expected topology.
4. **Hastings ratio symmetry:** Forward and reverse TBR proposals between
   two known topologies should produce Hastings ratios that satisfy
   detailed balance (sum to 0 in log space for the topology component).
5. **MCMC integration:** Short run with `tbr = TRUE` completes without
   error; acceptance rate is > 0.

## Correctness criteria

1. `R CMD check` passes with no warnings.
2. TBR proposal produces valid unrooted trees in canonical preorder.
3. Hastings ratio is correct — verified by:
   (a) Checking that tip-only prunes give the same result as SPR.
   (b) Manual calculation on a small (5-tip) tree.
4. MCMC with TBR enabled produces valid posterior samples (log-likelihood
   not degraded vs. SPR-only runs).
5. TBR acceptance rate is reasonable (> 0.5% on test datasets).

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| Rerooting logic is error-prone (path reversal on parent/child vectors) | Test extensively on small trees with known topology; compare to ape::root() output |
| Hastings ratio derivation error | Validate via reversibility check: for each forward TBR, compute the reverse and verify logHR_fwd + logHR_rev = 0 |
| Performance regression for users who don't use TBR | TBR is opt-in (`tbr = FALSE` default); no cost when disabled |
| TBR may not improve mixing on small trees | This is expected (M-091 showed Gibbs moves are worse per-second on small trees). TBR is positioned for large trees only. |

## Design decisions

1. **Opt-in via `tbr = TRUE`**, same pattern as `gibbsSpr`, `weightedSpr`.
   Default OFF because TBR is more expensive than SPR and only useful when
   SPR mixing is insufficient.

2. **Uniform reroot edge selection** within the pruned subtree. More
   sophisticated schemes (e.g., length-biased) could be added later but
   uniform is simplest and maintains easy Hastings ratio calculation.

3. **No Gibbs-TBR variant in this task.** A Gibbs version (enumerate all
   regraft × reroot combinations weighted by likelihood) would be O(N²)
   per proposal and is out of scope. Standard MH-TBR is sufficient as a
   first implementation.

4. **Reuse existing infrastructure:** `preorder_weighted_impl()` for
   canonical reordering, same proposal/accept/reject flow as SPR case 6.
