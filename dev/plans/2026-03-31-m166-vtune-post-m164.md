# M-166: VTune Re-profile Post M-164

## Goal

Verify that M-164's prior-ceiling pre-filter and LOG_CUTOFF tightening
reduced the Gibbs kPrime sweep's CPU share (baseline: 59.1%).

## Context

**Baseline (S-PROF round 4, pre-M-164):** VTune SW sampling, Sun2018,
54 taxa, 225 all-trans chars, nCat=6, ~15k iters. DLL built 09:57 BST
(before M-164 at 13:34 BST). Results in `vtune-out/`.

| Function | CPU Time | % |
|----------|----------|---|
| `pruning_jc_acrv_persite` | 53.0s | 59.1% |
| `_expl_internal` (exp) | 10.5s | 11.7% |
| `constant_site_prob_jc` | 5.9s | 6.6% |
| `pruning_jc_acrv_flat` | 3.5s | 3.9% |

Total elapsed: ~91.4s.

**Changes since baseline that affect the hot path:**

1. **M-164** (`bc1e2ee`): Prior-ceiling pre-filter for Gibbs kPrime
   sweep — skips tree traversals when prior+charMaxLL is below
   acceptance threshold. Also tightened LOG_CUTOFF from -57.5 → -25.0.
2. **M-158** (`be2f67b`): SPR partial CL evaluation — dirty-flag system
   for ~5× per-SPR-move speedup. Minor impact (~3.4% of moves are SPR).
3. **M-168 fix** (`25b5d88`), **pi[16] fix** (`6102a62`): Correctness
   fixes, no perf impact.
4. **M-169** (uncommitted in working tree): `het_constant_site_prob`
   rewrite — JC-only config, so no effect on this benchmark.

## Plan

### Step 1: Build with VTune symbols

Add profiling flags to `src/Makevars.win`:

```
PKG_CXXFLAGS = $(SHLIB_CXXFLAGS) -g -fno-omit-frame-pointer
```

Install to `.vtune-lib` with `DLLFLAGS=-static-libgcc` override:

```r
old_mf <- Sys.getenv("MAKEFLAGS")
Sys.setenv(MAKEFLAGS = "DLLFLAGS=-static-libgcc")
install.packages(".", lib = ".vtune-lib", repos = NULL,
                 type = "source", INSTALL_opts = "--no-multiarch")
Sys.setenv(MAKEFLAGS = old_mf)
```

### Step 2: Run VTune collection

Same config as baseline: SW sampling, driver script
`benchmark/vtune-driver.R`. Save to `vtune-out-m166/`.

```bash
"C:/Program Files (x86)/Intel/oneAPI/vtune/latest/bin64/vtune" \
  -collect hotspots -knob sampling-mode=sw \
  -result-dir vtune-out-m166 \
  -- Rscript "benchmark/vtune-driver.R"
```

### Step 3: Generate report & compare

```bash
vtune -report hotspots -result-dir vtune-out-m166
```

Compare against baseline (already loaded above). Key metrics:

- `constant_site_prob_jc` share (was 6.6%)
- `_expl_internal` (exp) share (was 11.7%)

## Risks

- SW sampling may have timing noise (±5% typical). Only meaningful
  changes (>10% relative) are actionable.
- M-164's pre-filter benefit depends on the prior distribution's shape
  during early/mid MCMC. A 15k-iter run includes warmup; the prior
  ceiling is most effective after the chain has settled near the
  posterior mode where many k' candidates are far from the posterior.
- Uncommitted M-169 changes in working tree. They don't affect this
  benchmark config (JC-only, no het), but will be compiled into the
  profiling build.
