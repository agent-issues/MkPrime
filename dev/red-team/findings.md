Severity scale: HIGH (correctness; affects results), MED (correctness;
narrow conditions or off-by-ε), LOW (perf, hygiene, latent), DOC (docs
mismatch with code, no immediate impact).

| R4-1 | HIGH    | OPEN     | Bug   | `initOverrides$tree_length` / `rel_br_lengths` silently ignored by init likelihood (smoking gun for 113-nat sample-1 gap) | `R/RunMkPrime.R:2792-2805, 2809-2836`. `.InitState()` applies overrides to `state$tree_length` and `state$rel_br_lengths`, but the subsequent `.MkpEcologyLogLikelihood(tree, ...)` / `.MkpLogLikelihood(tree, ...)` call reads `tree$edge.length` directly (see `R/likelihood.R:163, 188, 205`). | R4-2 | HIGH    | OPEN     | Bug   | `initOverrides$tree` bypasses preorder reordering — violates documented invariant | `R/RunMkPrime.R:2735` substitutes `tree <- overrides$tree` BEFORE the `.MkpEcologyLogLikelihood` call. | R4-3 | HIGH    | OPEN     | Bug   | C++ `cpp_log_prior` rejects theta ∈ {0,1} strict; R `LogPrior` accepts theta at the closed interval — mismatch | `src/mcmc.cpp:408` returns `R_NegInf` for `theta[e] <= 0.0 || theta[e] >= 1.0`, but `R/MkPrimeModel.R:668` accepts theta on closed `[0, 1]` and lines 691, 696 only short-circuit when the corresponding count is non-zero. L-4 row claims the R fix "mirrors C++" — it does NOT. R will return a finite log_prior at theta=0 (with zero enc cells) while C++ returns `-Inf`. Pilot evidence aligns: truth-init had to use theta=0.999 because theta=1.0 was rejected at the C++ boundary; the R init still produced a finite log_post for the same boundary state, hiding the impending rejection. Decide ONE convention and apply it both sides. The C++ strict-open choice is the safer one (no 0×log0 traps), but it means truth-init at boundary states needs explicit clamping. |

## Closing protocol

When a bug is fixed:
1. Update `Status: CLOSED`.
2. Reference the fix commit in the row.
3. Leave the row in the table (so future reviewers see what was found and where).

When a bug is deferred:
1. Update `Status: DEFERRED` and add a short reason.
2. Reference any tracking issue or upstream work.

When a finding turns out to be a false alarm:
1. Update `Status: DISMISSED` and add a one-line reason.
